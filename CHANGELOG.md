# История изменений

## 0.2.0 — 2026-09-07

### Добавлено

- Публичные точки входа `summarize_axes` и `summarize_meta`: первая отдельно считает
  axis-саммари, вторая собирает мета-нарратив из уже готовых саммари.
- Публичные модели результатов раздельных стадий `AxisSummariesResult` и `MetaResult`.
- Публичное исключение `MetaSummaryError`, которое при исчерпании попыток мета-вызова на
  пустом ответе сохраняет результат первой стадии.
- Публичная операция `Usage.__add__` для сложения usage раздельных стадий.
- `TooManyAxisFailures` теперь несёт `axis_summaries` только для успешно посчитавшихся
  осей, без заглушек на месте упавших, и накопленный `usage`.

Раздельные стадии позволяют потребителю сохранить уже посчитанные axis-саммари и после
провала мета-этапа восстановиться одним вызовом модели через `summarize_meta` вместо десяти.

Авторитетное описание API, сигнатур и поведения находится в [docs/api.md](docs/api.md).

### Наблюдаемое изменение

На неуспешных путях число обращений к провайдеру выросло до `max_attempts` там, где в v0.1
была одна попытка: успешный ответ без содержимого теперь повторяется как транзиентный отказ
(§5.2, D-028). Это видно через `usage.calls` и по длительности неуспешных прогонов. На
успешном пути ничего не изменилось: выход и число вызовов остались прежними.

Решение D-017 отменено решением D-028.

### Совместимость

Изменение строго аддитивно: `summarize()` сохраняет сигнатуру и поведение на успешном пути,
а существующий `except SummarizeError` продолжает ловить новый `MetaSummaryError`.
Потребителям, которым частичный результат не нужен, правки не требуются.

### Стабильность и область релиза

- Все шесть имён, введённых в v0.2, — `summarize_axes`, `summarize_meta`,
  `AxisSummariesResult`, `MetaResult`, `MetaSummaryError`, `Usage.__add__` — стабильны на
  протяжении `0.x` наравне с ядром. Это путь восстановления, на который потребитель
  опирается именно после сбоя, а не эксперимент.
- Весь `amnesiac.select` остаётся unstable на протяжении всего `0.x` (D-005).
  Потребителю, который от него зависит, следует фиксировать точную версию.
- `amnesiac.neuter` по-прежнему отсутствует и запланирован к релизу `0.3.0`.

### Отступления от `blind_prophet`

Авторитетный список приведён в [§9 публичного контракта](docs/api.md#9-отступления-от-кода-blind_prophet).
В v0.2 ровно восемь отступлений, с сохранением нумерации контракта:

1. `SummarizeResult` возвращает axis-саммари и usage — сейчас они теряются внутри пайплайна.
2. `print` заменён на `logging`.
3. Ограничитель параллелизма инжектируется снаружи вместо `asyncio.Semaphore(5)`, создаваемого
   внутри. Умолчание сохраняет прежнее значение 5.
4. Мета-вызов обёрнут в тот же ретрай, что и axis-вызовы. В исходном коде он не защищён
   вообще. На успешном пути выход не меняется, поэтому регресс не затрагивается.
5. Пустой ответ модели обрабатывается явно и **повторяется** как транзиентный отказ (§5.2).
   Оригинал этот случай не проверяет и уводит `None` дальше по пайплайну. Формулировка v0.1
   («приравнивается к отказу, повторная попытка не делается») заменена решением D-028. На
   успешном пути выход не меняется, поэтому регресс не затрагивается.
6. `asyncio.CancelledError`, возникшая на оси, пробрасывается наружу. Оригинал классифицирует
   отменённую ось как успешную — `isinstance(r, Exception)` ложно для наследника
   `BaseException`, — после чего объект исключения уходит в текст мета-промпта, а мета-вызов
   отправляется провайдеру. Порт как есть невозможен без нарушения §5.2 и §8. На успешном
   пути выход не меняется, поэтому регресс не затрагивается (D-020).
7. Список транзиентных отказов расширен на `RateLimitError` и `InternalServerError` (§5.2).
   Оригинал повторял только транспортные сбои, отдавая 429 и 5xx наружу с первой попытки. На
   успешном пути выход не меняется (D-029).
8. Исключения несут частичный результат: `TooManyAxisFailures` — посчитавшиеся оси,
   `MetaSummaryError` — результат первой стадии целиком (§8). В оригинале посчитанное
   теряется вместе с исключением. Наблюдаемо только на путях отказа (D-030, D-032).

Раздельные стадии (§5.8–5.10) и `Usage.__add__` (§5.7) не являются отступлениями: это новые
точки входа, а не иное поведение существующих. Поведение `summarize()` они не меняют.

## 0.1.0 — 2026-08-23

### Добавлено

- Публичный API корня пакета: `Doc`, `AmnesiacError`, `ConfigurationError`.
- Публичный API `amnesiac.summarize`: `summarize`, `PromptPack`, `PromptRenderError`,
  `SummarizeConfig`, `SummarizeError`, `SummarizeResult`, `TooManyAxisFailures`, `Usage`;
  замороженный пак промптов
  `amnesiac.summarize.prompts.RU_MACRO_V1`.
- Публичный API `amnesiac.select`: `select_by_axis`.
- `amnesiac[select]` устанавливает NumPy; для суммаризации дополнительный extra не нужен
  (D-015).

Авторитетное описание API, сигнатур и поведения находится в [docs/api.md](docs/api.md).

### Стабильность и область релиза

- Весь `amnesiac.select` нестабилен на протяжении `0.x` (D-005) и может измениться даже в
  патч-релизе. Потребителю, который от него зависит, следует фиксировать точную версию.
- `amnesiac.neuter` отсутствует в v0.1 и запланирован отдельным эпиком.
- Пакет содержит аннотации типов и маркер PEP 561 `py.typed`, но аннотации поставляются как
  есть и не проверяются статическим анализатором: `mypy` не входит в гейты на `0.x` (D-023).

### Отступления от `blind_prophet`

Авторитетный список приведён в [§9 публичного контракта](docs/api.md#9-отступления-от-кода-blind_prophet).
В v0.1 ровно шесть отступлений, с сохранением нумерации контракта:

1. `SummarizeResult` возвращает axis-саммари и usage, которые в исходном пайплайне теряются.
2. `print` заменён на `logging`.
3. Ограничитель параллелизма инжектируется снаружи вместо создаваемого внутри
   `asyncio.Semaphore(5)`; значение по умолчанию остаётся равным 5.
4. Мета-вызов обёрнут в тот же ретрай, что и axis-вызовы; в исходном коде он не защищён.
5. Пустой ответ модели обрабатывается явно; оригинал не проверяет его и передаёт `None`
   дальше по пайплайну.
6. Возникшая на оси `asyncio.CancelledError` пробрасывается наружу; оригинал классифицирует
   отменённую ось как успешную и отправляет объект исключения в мета-промпте.
